# Steady Web App Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Steady built for the browser from the same code: installable on an iPhone's Home Screen, data kept on the phone, phone-only features replaced or hidden, hosted on Vercel. Reminders come in plan 3.

**Architecture:**
- Expo's web support (react-native-web, Metro, `expo export --platform web`) builds the same expo-router app.
- Phone-only modules are reached through a few files that get a `*.web.ts(x)` twin. The biggest is a new `src/notify/port.ts`, the one place screens get the reminder port from. On the web, for now, it's an inert stand-in.
- `expo-sqlite`'s WebAssembly mode keeps the database. It needs cross-origin isolation headers from Metro (development) and Vercel (production).
- An install-first screen, a web manifest and a small service worker make it an app.

**Tech Stack:** Expo SDK 58, react-native-web, `@expo/metro-runtime`, `expo-sqlite` (web, wa-sqlite + OPFS), Vercel (static hosting, team `bhccob`, free plan), a hand-written service worker.

**Spec:** `docs/superpowers/specs/2026-10-30-steady-web-app-design.md`, sections 1, 2 and 4, Constraints, Risks (risk 1 is the gate in Task 2).

## Global Constraints

- Install packages with `npx expo install`, never plain `npm install`, so versions match SDK 58.
- Headers on every response: `Cross-Origin-Opener-Policy: same-origin` and `Cross-Origin-Embedder-Policy: credentialless`. Switch to `require-corp` if Safari on iOS doesn't report `crossOriginIsolated === true` with `credentialless`.
- Everything the web app loads comes from its own address: no fonts, scripts, analytics or images from elsewhere.
- Manifest: `display: standalone`, `orientation: portrait`, `start_url` and `scope` `/`, theme and background colour Paper `#F5F3EF`, name "Steady". Icons come from `brand/icons/web/`.
- The Android app is unchanged in behaviour. `npm test`, `npm run lint` and `npm run typecheck` pass, and `npx expo-doctor` stays 20/20.
- The web address isn't advertised (README, releases) in this plan. That waits for plan 3 and the owner's iPhone check.

## Review Focus

1. **The app opened in a Safari tab, not installed.** It must land on the install screen, not run setup, because a tab's data is lost on install. Task 4's `installStep` tests pin this.
2. **The app reloaded or reopened after setup.** Data must still be there (no re-onboarding). Task 1's browser check and Task 2's iPhone check cover it.
3. **A phone-only module imported at web startup**, crashing the bundle before any screen. Task 1's `build:web` plus loading the built app in a browser catches it, and the import guard test in Task 1 pins the known ones.
4. **Install on Android Chrome.** The prompt must come from the install screen's button, and a dismissed prompt must not trap the person. Task 4's `installStep` tests cover the no-prompt path.
5. **Offline open of an installed app.** It must open from cache, not show the browser's offline page. Task 5's check in the browser pane covers it, by reloading offline.

### Task 5: Opens offline, keeps its data, glow made for the web

**Files:**
- Create:
  - `public/sw.js`, the service worker. `install` caches `/` and `/index.html`. `fetch` uses network-first for navigations, falling back to the cached `/index.html`, and cache-first for `/_expo/static/` and `/assets/`. `activate` clears old caches by a `CACHE` version string.
  - `src/web/registerServiceWorker.ts`, which registers `/sw.js` after load, on the web only.
  - `src/web/persist.ts`, which calls `navigator.storage?.persist?.()` once when standalone.
  - `src/ui/Background.web.tsx`, the same layers as plan 1's `Background.tsx`, but animated with react-native-web's CSS keyframes (`animationKeyframes`, `animationDuration` = `periodMs`, `animationDirection: 'alternate'`, `animationIterationCount: 'infinite'`, `animationTimingFunction: 'ease-in-out'`), with values from `ambientAt(l, 0)` and `ambientAt(l, 1)`. It's still when `ambientOn` is false.
- Modify: `app/_layout.tsx` (call `registerServiceWorker()` and `persist()` on the web)
